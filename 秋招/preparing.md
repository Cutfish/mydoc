### 4. golang内存管理

内存管理分为两块，一个是分配一个是回收。分配涉及堆栈分配，回收是堆区内存GC。

分配在堆栈主要是进行对象的生命周期判断或者说是否存在内存逃逸等手段，选择对象分配在栈区或者是堆区。分配在栈的变量随着栈的销毁自动回收，堆分配的对象需要GC来进行回收。

下面的堆分配的基本原理：

1. mcache（线程本地缓存）
   每个 P（逻辑处理器） 绑定一个 mcache。

里面按 size class（大小等级） 缓存了一堆 mspan（内存块）。

分配小对象时，直接从 mcache 拿，无需加锁，速度极快。

2. mcentral（中心缓存）
   全局结构，按 size class 划分。

当 mcache 中的某个 size class 用完了，就向 mcentral 申请。

mcentral 需要加锁，但只锁对应的 size class，粒度较细。

3. mheap（堆）
   全局唯一，管理所有从操作系统申请的内存。

当 mcentral 也不够时，向 mheap 申请。

mheap 以 页（page，8KB） 为单位管理内存，向 OS 申请大块内存（如 64MB 的 arena）。

二、内存分级：Size Class
Go 把对象按大小分为三类，走不同分配路径：

类型	大小范围	分配方式
Tiny 对象	< 16 字节	合并分配到同一个 16 字节块，减少浪费
Small 对象	16 字节 ~ 32KB	从 mcache 的对应 size class 分配
Large 对象	> 32KB	直接从 mheap 分配，绕过 mcache/mcentral
Size Class 大约有 67 种（如 8B、16B、24B、32B…直到 32KB），每个 size class 对应一种 mspan。这样做的目的是减少内存碎片——分配 24 字节的对象，就给它 24 字节的块，而不是按 2 的幂次给 32 字节。

三、mspan：内存管理的基本单位
mspan 是 Go 管理内存的基本单元，由连续的页组成。

go
type mspan struct {
    startAddr uintptr   // 起始地址
    npages    uintptr   // 占用的页数
    nelems    uintptr   // 能分配多少个对象
    freeindex uintptr   // 下一个空闲对象的索引
    allocBits *gcBits   // 分配位图
    ...
}
一个 mspan 被切分成等大的对象（大小由 size class 决定）。

freeindex 指向下一个可分配的位置，分配时只需移动指针。

当 mspan 中所有对象都分配完，就变成 "full"，从 mcache 中移除，换一个有空闲的。

四、分配流程（以 Small 对象为例）
text

1. 计算对象大小 → 找到对应的 size class
2. 从当前 P 的 mcache 中取出对应 size class 的 mspan
3. 如果 mspan 有空闲 slot → 直接分配，移动 freeindex（无锁，极快）
4. 如果 mspan 满了 → 向 mcentral 申请一个新的 mspan
5. 如果 mcentral 也没有 → 向 mheap 申请
6. 如果 mheap 也没有 → 向操作系统申请内存（sysAlloc / mmap）

五、栈内存分配

除了堆，Go 还有栈分配：

每个 goroutine 有自己的栈，初始 2KB。

编译器通过逃逸分析（Escape Analysis） 决定变量分配在栈还是堆。

如果变量不会逃出函数作用域 → 分配在栈上，函数返回自动回收，无需 GC。

如果逃逸（如返回指针、被闭包捕获）→ 分配在堆上，由 GC 管理。

栈是可增长的：当栈空间不足时，Go 会分配一个更大的栈并复制内容（栈扩容/缩容）。

逃逸分析是性能优化的关键：能用栈就不用堆，减少 GC 压力。

七、为什么要这样设计？
设计	目的
mcache 无锁分配	避免多线程竞争，提升并发性能
多级缓存	平衡速度与内存利用率
Size Class 分级	减少内存碎片
Tiny 对象合并	小对象不浪费空间
逃逸分析	尽量栈分配，减轻 GC
页 + mspan 管理	灵活管理不同大小的内存

### 5.map的时间复杂度

为什么说map的增删改查时间复杂度都是O（1），明明是存在hash计算和扩容时候的O（n）的时间复杂度

1. **O(1) 指常数时间，不是零时间** 。哈希计算确实耗时，但它不随数据规模增长。
2. O(1) 是**平均/均摊**结论，建立在哈希均匀、动态扩容均摊的前提上。
3. **最坏情况是 O(n)** ，当哈希冲突严重时会发生。

Go 的 map 底层是 **哈希表 + 桶（bucket）** ：

* 每个桶存 8 个 key-value。
* 哈希值的低位决定去哪个桶，高位用于桶内快速比较。
* 当装载因子过高（元素/桶 > 6.5）时触发扩容，桶数量翻倍。

### 9.限流算法实现

- 漏桶：比如维护一个hash类型的键值对，有一个water和上次请求时间，每次请求的时候，先把水放掉，可以按照（当前时间减去上次请求时间）* 速率，用当前水量减去刚才漏掉的水，然后判断water > capacity，如果是的那就限制，否则就可以通行。
- 令牌桶：设置一个hash类型key，包括两个字段，一个是时间一个剩余请求次数，每次请求的时候用（当前时间 - 上次请求时间） * 限流频率加在剩余请求次数中，每次请求的时候剩余请求次数减一。大于固定单位的时间统一按照固定单位计算。
- 固定窗口：每分钟设置一个key，每次有请求在对应分钟内计数，一分钟后过期
- 滑动窗口：维护一个redis的zset，member用唯一标识符（比如uuid）score是请求时间戳（毫秒级），每次请求来的时候，按照窗口大小，给比如1s之间的元素全都删除，然后统计zset元素数量，然后判断count < limit

### 10.TLS握手

> 客户端发送支持的加密算法列表、随机数（Client Random）等信息。

> 服务器选择加密算法（如 AES-256-GCM），返回随机数（Server Random）和数字证书（含公钥）。

> 客户端验证证书有效性（如颁发机构、有效期、域名匹配）。 密钥交换。客户端用服务器公钥加密一个随机值（Pre-Master Secret），发送给服务器。

> 会话密钥生成：双方通过 Client Random、Server Random 和 Pre-Master Secret 生成相同的对称密钥（Session Key）。

后期就采用：对称加密通信 后续所有数据传输均使用 Session Key 对称加密（如 AES），效率更高。 每次会话的密钥独立，避免长期密钥泄露风险。

### 11.Mass、Fass、Pass服务都是什么意思

它们都是云计算中的服务模式，区别在于云服务商向开发者提供什么能力。

- MaaS（模型即服务）

将 AI 模型封装为服务，开发者不需要自己训练、部署模型，直接通过 API 调用。

- PaaS（平台即服务）

云服务商提供应用程序所需的运行环境和部署平台，开发者主要负责应用代码和业务逻辑。

- FaaS（函数即服务）

开发者只需要编写业务函数，云平台负责函数的运行、资源管理和弹性扩缩容。

### 11.Redis AOF & RDB

AOF 平时追加写入不需要为每次写入创建子进程；RDB 每次生成快照都要 `fork`。不过 **AOF 重写时也会 `fork`**

写时复制：

* Redis 创建一个子进程。子进程负责把当时的数据写入快照。
* 刚创建时，父子进程 **共享内存页** ，不会立刻复制整个数据集。
* 如果此时客户端修改数据，父进程要改到的内存页会先被复制。子进程继续看旧页，保证快照内容不被后续写入改变；父进程使用新页继续处理请求。

所以在写时复制时候，如果有大量的修改数据会导致内存占用骤增。

所以最好选择RDB。

AOF  **平时是不断追加写命令** ；“重写”是定期把累积的历史操作整理成一份能恢复**当前数据**的更紧凑文件。比如同一个 key 被 `INCR` 100 次，重写时不必保留这 100 次历史操作。**自动触发** ：AOF 文件达到最小大小，并且相对上次重写后的大小增长达到设定比例。也有手动触发。

### 14.限流熔断降级

机制	触发依据	目的
限流	QPS、并发数超过阈值	防止流量过大
熔断	下游错误率、超时率过高	隔离故障服务
降级	系统故障或资源不足	保留核心功能

例如：

- 限流：每秒只允许 1000 个请求。
- 熔断：最近 100 个请求中，60% 失败，暂停调用下游 30 秒。
- 降级：支付服务不可用时，返回“支付功能暂时不可用”，但商品浏览功能正常。
